# Inputs needed to finish the remaining gates

Do not put passwords, API hashes, keystores, Apple certificates or Telegram login codes in Git or chat. Give the maintainer a secure local/CI secret location and its variable names.

1. **Telegram app and test account.** Sign in to [my.telegram.org](https://my.telegram.org/), open **API development tools**, create this app's `api_id` and `api_hash`, and store them outside the repository. Supply a dedicated account for Saved Messages/private-chat import tests. Channels and groups are disabled by the user's scope choice. The [Telegram API terms](https://core.telegram.org/api/terms) require an app-specific ID, prominent API disclosure and ordinary client behavior; obtain a compliance review of this limited scope before enabling TDLib.
2. **Rights for online lyrics and audio.** The user prefers general web discovery, so the app now offers MusicBrainz recording metadata search without audio download. Google result snippets and public download links do not grant permission to reproduce full lyrics or store audio. To enable those features, supply a rights-granting source or agreement for each use, including attribution, offline-copy terms, rate limits and any secure credential location. MusicBrainz's free API use is non-commercial; decide whether the release is commercial before enabling it in a distributed build.
3. **App identity and distribution.** Choose final Android `applicationId`, iOS bundle ID, display name and store owner. For Android, create a Play Console app and an upload key using [Android's signing guide](https://developer.android.com/studio/publish/app-signing); keep the keystore outside Git. For iOS, enroll in the [Apple Developer Program](https://developer.apple.com/programs/enroll/) and provide the team ID and access to certificates/profiles on a Mac or trusted CI.
4. **Device verification.** Provide access to at least one physical Android device and one iPhone, plus owned MP3/FLAC/M4A and malformed/large-file fixtures. Run or share logs for the import, playback, background, screen-reader, interruption and 24-hour soak gates. Simulator results do not close these gates.
5. **iOS CI follow-up.** [Run 37124962862](https://github.com/Nima-Moradi1/music-player/actions/runs/37124962862) passed simulator build, launch and Foundation UI tests after two earlier iOS smoke failures. No artifact is needed while the failure is not reproducible. If it returns, send the failure annotation from the updated script or `foundation-ui.log` inside the `ios-simulator-smoke` artifact. Android investigation is deferred at the user's request.

The Android Gradle release configuration reads `MUSIC_PLAYER_UPLOAD_KEYSTORE`, `MUSIC_PLAYER_UPLOAD_STORE_PASSWORD`, `MUSIC_PLAYER_UPLOAD_KEY_ALIAS`, `MUSIC_PLAYER_UPLOAD_KEY_PASSWORD`, `MUSIC_PLAYER_VERSION_CODE` and `MUSIC_PLAYER_VERSION_NAME`. The first four must be set together to produce signed release artifacts. An unsigned release preflight is available via `.github/workflows/release-preflight.yml` and has not yet been run.
